# Decision Arena

A 9B **decision model** against a general **chat model**, on five everyday decisions.

[elephant-1](https://www.baseten.co/library/elephant-1/) (Base Labs, on Baseten) doesn't write text. You give it a situation and some questions, and it returns a calibrated probability for every option in one pass. The challenger, DeepSeek V4.1 Flash by default, is a normal chat model asked to do the same thing and report its probabilities as JSON.

The question isn't only *who picks right more often*. It's also:

- **Calibration**: when a model says 80%, is it right 80% of the time? (Brier score, ECE, reliability chart)
- **Stability**: does the answer change when the options are listed in reverse order? (flip rate)
- **Cost and latency** per 1,000 decisions
- **Cascade**: let elephant-1 decide and escalate only the unsure cases to the chat model. How much accuracy does that buy per dollar?

## The five use cases

| Use case | Questions | For |
|---|---|---|
| GitHub issue triage | label (choice), urgency (score) | developers |
| Pull request gate | needs review (yes/no), risk (score) | developers |
| Scam check | is it a scam (yes/no), kind (choice) | everyone |
| Screenshot judge | broken (yes/no), defect (choice), **image input** | both |
| Apartment fit | fit (score), dealbreaker (yes/no) | everyone |

Each comes with 12–16 hand-labelled items in `src/lib/usecases/`. Some are ambiguous on purpose. The screenshots are generated by `scripts/render-screens.mjs` with headless Chrome. This is a small demo set, not a leaderboard.

## Run it locally

```bash
npm install
cp .env.example .env.local   # then fill in the two keys
npm run dev
```

- `BASETEN_API_KEY`: from your Baseten account
- `CHALLENGER_API_KEY`: an OpenCode Go key by default. DeepSeek API and OpenRouter work too (pick them under **API keys** in the app).

Without `.env.local`, paste the keys into the **API keys** dialog instead. They are kept in your browser's localStorage.

## Deploy (bring your own key)

Deploy to Vercel **without** setting the two env vars. Each visitor then uses their own keys, which pass through `/api/decide` per request and are never stored. The proxy only forwards to Baseten and the three allow-listed challenger hosts.

To show results to visitors who have no keys, run the benchmark, click **Export**, and commit the file as `public/results/latest.json`. The app shows it until a visitor runs their own.

## How it works

```
browser ── /api/decide ──┬─▶ Baseten System One API     (elephant-1: probabilities)
 (keys in headers)       └─▶ OpenAI-compatible chat API (challenger: JSON probabilities)
```

- `src/lib/server/elephant.ts` passes requests to Baseten's `/v1/systemone` almost unchanged.
- `src/lib/server/challenger.ts` turns the same request into a prompt and parses the probabilities back.
- `src/lib/bench.ts` holds the metrics (accuracy, Brier, ECE, flip rate) and the cascade simulation.
